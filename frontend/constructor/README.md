# Конструктор сценариев

Визуальный редактор `Flow` для уже зарегистрированных Telegram- и MAX-ботов.
Редактор не генерирует код и не регистрирует бота на платформе: он собирает
сценарий как данные, сохраняет черновик через Admin API и передаёт его Flow Engine.

## Запуск и проверка

```bash
cd frontend/constructor
npm install
npm run dev       # http://127.0.0.1:5173
npm test          # API-ошибки, контракт сериализации и работа с выделением
npm run build
```

Dev-server проксирует `/api` и `/healthchecks` на `http://127.0.0.1:8000`.

## Основной путь

1. Выберите платформу и подключите уже созданного бота его токеном.
2. Соберите сценарий из входов, сообщений, вопросов, логики, Mini App и интеграций.
3. Проверьте граф: ошибки кликабельны и ведут к соответствующему узлу.
4. Сохраните черновик, затем опубликуйте текущую сохранённую версию.

После подключения платформа блокируется: это соответствует инварианту `Bot.platform`.
Технические `bot_id` и `row_version` остаются внутренним состоянием редактора.

## Что поддержано

- Палитра Flow Engine v1: `send_message`, `show_buttons`, `ask`, `condition`,
  `open_mini_app`, `save`, `http_request`, `notify`; `custom_code` показан как
  будущий sandbox-блок.
- Для всех кнопок с действием `next` есть подписанная связь на холсте. Выбор
  следующего блока в инспекторе и связь синхронизированы, поэтому схема всегда
  показывает реальную логику `Button.target`.
- Связи на холсте — адаптивные кривые: перетаскивайте саму линию или её плашку,
  чтобы аккуратно проложить маршрут; при перемещении узлов линия и подпись
  перестраиваются. Конечную точку стрелки можно перетащить на другой блок —
  целевой переход и `Button.target` синхронизируются автоматически.
- Групповое редактирование: тяните рамку по пустому холсту или добавляйте элементы
  через Ctrl/⌘-клик; выделенные блоки перемещаются вместе. Ctrl/⌘+C и Ctrl/⌘+V
  копируют блоки с внутренними переходами, Delete/Backspace удаляет выделенное,
  Ctrl/⌘+A выбирает всё. Esc, крестик панели или клик по пустому холсту очищают
  выделение и внутренний буфер. Счётчик выделения отдельно показывает узлы и
  связи; внешние связи намеренно не копируются.
- Небольшой стартовый шаблон «приветствие → меню → заявка/справка», а не
  специализированный AI-бот. Интеграции добавляются только при необходимости.
- Локальная проверка структуры, доступности блоков по CapabilityMatrix,
  достижимости, обязательных полей, кнопок и Mini App перед публикацией.
- Ошибки API нормализуются в понятные сообщения: FastAPI-валидация выводит поля,
  а 404/409/5xx и недоступный сервер не показывают технические детали. Проблемы
  графа видны на самих узлах, перечислены целиком и ведут к нужному месту на схеме.
- Пока выполняется запрос публикации, остальные действия блокируются; при ошибке
  рендера вместо пустого экрана выводится безопасный экран восстановления.
- Пошаговая панель публикации: подключение бота, сохранение черновика, публикация;
  привязка HTTPS Mini App, секреты HTTP-интеграций и роли уведомлений находятся в
  отдельных разделах.
- Открытие существующего сценария: раздел «Мои боты» показывает всех ботов
  сервера (`GET /api/bots`) и открывает сценарий в один клик; открыть можно и по
  ID бота, а у подключённого — перечитать с сервера (штатный выход из
  409-конфликта). Загрузка использует read-контракт `GET /api/bots/{id}/flow`
  (204 — черновика ещё нет, канва остаётся чистой), подхватывает `row_version`
  для безопасного сохранения и предупреждает, если несохранённые изменения
  будут заменены. Позиции узлов в definition не хранятся — раскладка
  восстанавливается детерминированным автолейаутом (ADR-0015); params сценария
  шире каталога (например, `values` у save) и кнопки-быстрые ответы на `ask`
  проходят через открытие/сохранение без потерь.
- На десктопе ширину палитры, панели настроек/публикации и панели «Данные Flow»
  можно менять перетаскиванием границы. Для клавиатуры используйте стрелки
  (Shift — крупный шаг), Home/End; двойной щелчок возвращает стандартную ширину.
  Выбранные размеры сохраняются только локально в браузере и не попадают в Flow
  или API. На узких экранах панели остаются drawer-окнами, чтобы не перекрывать
  весь холст.
- Токены и значения integration secrets вводятся в password-полях, не входят в
  Flow JSON и очищаются из состояния компонента после успешного запроса. Токен
  подключения отправляется только на текущий origin или локальный API.

## Ограничения текущего Admin API

- Ручная раскладка узлов и изгибы связей живут только в открытом сеансе
  редактора: в контракт исполняемого Flow они не входят, при открытии сценария
  применяется автолейаут. Персистентный layout — вариант 4 в ADR-0015,
  ждёт ратификации.
- Подключение по токену идемпотентно (BR-009, ADR-0016): повторный connect
  того же токена возвращает существующего бота, и если у него есть сценарий —
  конструктор сразу предлагает открыть его. Боты, подключённые до введения
  отпечатка токена, дедупликации не подлежат (у них нет отпечатка).
- Быстрые ответы у «Задать вопрос и ждать» (нажатие сохраняет значение как
  ответ) и список «Несколько значений разом» у «Сохранить значение» (values,
  пустое значение стирает переменную — BR-008) редактируются в панели настроек.
  Если у ask есть скрипт-авторские кнопки с переходами, показывается полный
  редактор кнопок, чтобы не ломать связи.
- Публикация проверяет токен через платформу на backend. Сам редактор не делает
  прямых вызовов Telegram или MAX.
- `custom_code`, платежи, продовый vault/IAM и гарантированная доставка уведомлений
  остаются отдельными этапами.
