# ADR-0015: Открытие сценария в редакторе и судьба layout

## Контекст

Read-контракт черновика (`GET /api/bots/{id}/flow` → definition + row_version)
реализован на бэкенде, и редактор теперь открывает существующий сценарий
(десериализатор `frontend/constructor/src/flow/deserialize.js`). Но definition —
канонический документ `src/domain/flow/codec.py`, SSoT логики сценария:
позиции узлов канвы в нём не хранятся, а неизвестные поля кодек молча
отбрасывает при ре-сериализации на PUT (definition → Flow → definition).
Авторская раскладка канвы теряется между сеансами; «положить position в
definition» без изменения кодека невозможно — поле не переживёт раундтрип.
Дополнительная сила: `definition_hash` — основа идемпотентности publish
и дедупликации версий; всё, что попадает в definition, меняет hash.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| 1. Оставить как есть (не открывать сценарий) | ничего не делать | редактор бесполезен для существующих ботов; 409-конфликт без выхода |
| 2. Детерминированный автолейаут на клиенте при открытии | контракт не меняется; работает для всех уже сохранённых черновиков; нулевая цена на бэкенде | авторская раскладка теряется — каждый сеанс начинается с автолейаута |
| 3. `position` внутрь `node.params` | переживает раундтрип уже сегодня | позиции попадают в `definition_hash` и в published-версию: сдвиг узла = «изменённый» сценарий, ломается идемпотентность publish |
| 4. Top-level `layout` в definition, исключённый из `definition_hash` | авторская раскладка персистентна; логика и вид разделены | изменение кодека и семантики hash (миграция не нужна, но контракт растёт); нужен явный контракт «layout не влияет на публикацию» |

## Решение

Сейчас (реализовано): **вариант 2** — при открытии сценария раскладка
восстанавливается детерминированным послойным автолейаутом (BFS от триггеров,
недостижимые блоки рядами ниже графа; `deserialize.js`). Definition остаётся
чистой логикой сценария.

Целевой вариант на ратификацию команды: **вариант 4** — top-level поле
`layout: {node_id: {x, y}}` в definition, которое кодек сохраняет, но
`definition_hash` игнорирует (hash считается по документу без `layout`).
До ратификации кодек не трогаем.

Граница решения: касается только представления канвы конструктора; Flow
Engine, движок публикации и вебхук-контур раскладку не читают никогда.

## Последствия

**Положительные:**
- Открытие существующего сценария работает для всех ботов, включая созданных
  до фичи и скриптами (проверено на живых ботах examples/first-bot: раундтрип
  definition без потерь).
- Идемпотентность publish и `definition_hash` не затронуты.

**Отрицательные:**
- Авторская раскладка пока не переживает сеанс — после открытия узлы стоят
  по автолейауту, не как их расставил автор.

**Риски:**
- Если вариант 4 отклонят, останется постоянная UX-цена автолейаута; сигнал
  для пересмотра — жалобы на «разъехавшиеся» большие сценарии (50+ узлов).
