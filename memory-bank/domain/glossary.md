# Глоссарий meta-bot-core

Канонический словарь предметной области (ubiquitous language). Здесь фиксируется,
как термин звучит в разговоре и как он **обязан** называться в коде. Имена отсюда —
источник истины для сущностей, портов, событий и блоков сценария.

## Правило единого языка

- **Термин в коде обязан совпадать с глоссарием.** Класс, таблица, поле API,
  событие — везде используется `Имя в коде` из таблицы ниже, без синонимов.
- Нашёл в коде синоним или «почти тот же» термин — это противоречие; действуй
  по [../_meta/lifecycle.md](../_meta/lifecycle.md) (раздел «Противоречия»).
- Переименование термина = правка этой таблицы + переименование в коде в одном PR
  (владелец раздела — [../_meta/governance.md](../_meta/governance.md)).
- Один термин — одна строка. Значение зависит от контекста — заведи две строки
  с разными значениями колонки «Контекст» (контексты — [bounded-contexts.md](bounded-contexts.md)).

## Таблица терминов

| Термин (рус.) | Значение | Имя в коде | Контекст |
|---|---|---|---|
| Бот | Подключённый к конструктору платформенный бот: платформа + токен + сценарий. Конструктор не создаёт платформенный аккаунт, а управляет поведением уже зарегистрированного бота | `Bot` | Constructor |
| Платформа | Мессенджер, в котором работает бот: Telegram или MAX (расширяемо: VK, WhatsApp). Value object | `Platform` | Constructor |
| Токен | Секрет платформенного бота, связывающий его с конструктором. Хранится в token vault, не в открытом виде и не в логах | `Token` | Constructor |
| Сценарий | Граф шагов и переходов, описывающий поведение бота: что и в каком порядке происходит | `Flow` | Constructor |
| Узел | Один шаг сценария (отправить сообщение, показать кнопки, спросить, условие, открыть mini app, custom-код). Данные, а не изображение | `Node` | Constructor |
| Триггер | Условие входа в сценарий/ветку: команда `/start`, текст, нажатие кнопки, результат mini app | `Trigger` | Constructor |
| Кнопка | Единая модель кнопки: подпись + действие (открыть mini app, callback, ссылка, следующий шаг). В платформенное представление превращает адаптер | `Button` | Constructor |
| Mini app | Web-приложение, привязанное к боту и запускаемое из кнопки. Автономно не существует (в MAX — только внутри чат-бота) | `MiniApp` | MiniApp |
| Входящее событие | Единая, платформонезависимая модель события от пользователя: платформа, бот, пользователь, чат, тип, текст, payload, `update_id` (ключ идемпотентности), `callback_id` (подтверждение нажатия), `message_id` (только для callback — правка на месте, ADR-0012) | `IncomingEvent` | FlowExecution |
| Нажатие кнопки | Событие нажатия кнопки/callback от пользователя | `ButtonClicked` | FlowExecution |
| Открытие mini app | Событие запуска mini app пользователем | `MiniAppOpened` | FlowExecution |
| Состояние пользователя | Текущий шаг пользователя в сценарии и его переменные (FSM). Одно активное состояние на пару (бот, пользователь) | `Session` | FlowExecution |
| Python-блок | Пользовательская чистая функция `run(context) -> dict` внутри сценария; исполняется изолированно, без доступа к БД, токенам, ФС, env, сети | `CustomCodeBlock` | CodeExecution |
| Адресат уведомления | Привязка символической роли сценария (`admin`, `developer`, …) к chat_id получателя. Конфигурация бота, не часть сценария: chat_id (потенциальные ПДн) не попадает в Flow | `NotificationTarget` (роль → chat_id за портом) | Constructor |
| Матрица возможностей | Реестр того, какие возможности доступны на каждой платформе (текст, кнопки, mini app, платежи, авторизация) | `CapabilityMatrix` | PlatformIntegration |
| Адаптер платформы | Реализация порта `BotPlatformPort` под конкретную платформу: маппинг команд, парсинг update, mini app-авторизация | `TelegramBotAdapter`, `MaxBotAdapter` | PlatformIntegration |

## Порты (интерфейсы приложения к инфраструктуре)

Имена портов тоже канонические — они пересекают границу слоёв и должны совпадать
с [../architecture/overview.md](../architecture/overview.md) и [patterns.md](../architecture/patterns.md).

| Порт | Назначение |
|---|---|
| `BotPlatformPort` | Отправка сообщений/кнопок, ответ на callback, построение кнопки mini app — абстракция над Telegram/MAX |
| `BotRepository` | Хранение и чтение агрегата `Bot` |
| `FlowRepository` | Хранение и чтение сценариев (`Flow`) |
| `SessionRepository` | Хранение состояния пользователя (`Session`) |
| `SessionRetentionPort` | Ретеншен ПДн сессий (BR-008): просрочка неактивных и удаление завершённых |
| `TokenVaultPort` | Безопасное хранение и выдача токенов ботов |
| `NotificationTargetResolverPort` | Резолв роли адресата уведомлений в chat_id платформы (блок `notify`, ADR-0010) |
| `NotificationTargetWriterPort` | Привязка роли адресата уведомлений к chat_id (Admin API, ADR-0010) |
| `SecretResolverPort` | Чтение секрета подключения (`{{secret:имя}}`) для блока `http_request` |
| `ConnectionSecretWriterPort` | Запись секрета подключения (Admin API) |
| `CodeExecutorPort` | Исполнение Python-блока в изоляции |
| `FileStoragePort` | Хранение файлов/медиа (план — порта в коде пока нет) |

## Как пополнять глоссарий

- [ ] Термин звучит так, как его произносит бизнес/пользователь конструктора?
- [ ] Значение — в одном-двух предложениях, без «см. код»?
- [ ] `Имя в коде` — английское, в нотации из [../architecture/code-style.md](../architecture/code-style.md)?
- [ ] Указан контекст из [bounded-contexts.md](bounded-contexts.md)?
- [ ] Нет строки-синонима? (Синонимы запрещены — выбери один термин.)

## Что глоссарий НЕ описывает

- Инварианты и связи сущностей — [domain-model.md](domain-model.md).
- Правила поведения («бот публикуется только с валидным токеном») —
  [business-rules.md](business-rules.md).
- Технические термины стека (FastAPI, Redis, webhook) — здесь им не место,
  только предметная область.
