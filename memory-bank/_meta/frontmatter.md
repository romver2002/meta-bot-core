# Схема frontmatter

Каждый `.md` в `memory-bank/` начинается с YAML-frontmatter. Это и есть
версионирование «в тексте»: агент не видит git log, поэтому версия, дата и статус
живут в самом документе. Валидатор проверяет схему автоматически.

## Обязательные поля

```yaml
---
status: active            # draft | active | archived
version: "1.3"            # мажор.минор (не semver — patch-компонента нет); поднимает автоматика
updated: 2026-07-05       # дата последней правки тела (ISO, YYYY-MM-DD); ставит автоматика
verified_commit: ""       # хеш коммита кода, на который документ проверен (может быть пустым)
owner: ""                 # ответственная роль/человек (может быть пустым)
---
```

### status
- `draft` — черновик: наполняется, на него нельзя опираться без проверки.
- `active` — действующий документ, источник истины.
- `archived` — устарел, хранится для истории; агент не использует его как истину.

### version
- Строка `"мажор.минор"` в кавычках. Это **не semver**: patch-компонента нет,
  сравнение и рост идут по двум числам (`1.9 → 1.10`, а не `1.10 < 1.9`).
- **Минор +1 — на любое изменение тела документа.** Автоматика не отличает
  опечатку от смысловой правки, поэтому поднимает минор при любом отличии тела
  от базовой ревизии. Это безопаснее, чем пропустить смысловую правку; подробности
  изменения остаются в git. Правка только frontmatter минор не поднимает.
- **Мажор +1 (минор в 0) — вручную**, когда документ существенно переработан или
  изменил охват. Ручной мажорный или минорный подъём автоматика уважает, если новая
  версия строго больше базовой, и повторно её не поднимает.
- **Версия не едет назад.** Если при изменении тела версия осталась прежней или
  была понижена, автоматика чинит или блокирует правку как непроставленный bump.
  При починке минор поднимается от версии в базовой ревизии, а не от ошибочно
  пониженного значения.
- Версию и дату проставляет `scripts/bump_frontmatter.py`: локальный pre-commit-хук
  включается однократно командой `python scripts/setup.py` (в этом проекте также
  доступно `uv run python scripts/setup.py`), а CI не пропускает изменение тела без
  корректного bump. Вручную `version`/`updated` поднимать не нужно.
- Исключение — документы `current/`: их frontmatter ведёт `scripts/mb_log.py`,
  поэтому CI-рубеж не требует от них отдельного bump. Если локальный хук не включён,
  недостающий bump остальных документов поймает CI.

### updated
- Дата последней правки тела (ISO). Ставится автоматикой вместе с подъёмом `version`.

### verified_commit
- Короткий хеш коммита кода, на момент которого документ проверен на соответствие
  реальности. Позволяет агенту понять отставание: `git log <hash>..HEAD -- <каталог>`
  покажет, что менялось в коде после последней сверки.
- Заполняется при сверке документа с кодом (см. [lifecycle.md](lifecycle.md)).
  Пустая строка = сверка не проводилась.

## Опциональные поля

```yaml
derived_from:             # канонические документы, из которых выведен этот
  - ../domain/domain-model.md
supersedes: "0003"        # только для ADR: номер решения, которое заменяет
decision_status: accepted # только для ADR: proposed | accepted | superseded | rejected
tags: [billing, api]
```

- `derived_from` — если факт в этом документе производен от другого, правится
  сначала канонический документ (правило «сверху вниз», см. [lifecycle.md](lifecycle.md)).
- `decision_status` — жизненный цикл ADR; сам файл ADR после `accepted`
  по существу не редактируется (см. [../decisions/README.md](../decisions/README.md)).

## Чего в frontmatter НЕ делаем

- **Не ведём changelog внутри документа.** История правок — это git.
  Frontmatter отвечает только на вопросы «насколько свежо» и «можно ли верить».
- Не дублируем содержимое (заголовок, описание) — это тело документа.
